# CoinGecko Crypto Market Report

Automated crypto market analysis deployed to GitHub Pages.

## 🌐 Live Report
**https://bruce-cham.github.io/CoinGecko/**

## 📊 What's Included
- **Market Structure**: Total cap, BTC/ETH dominance, volume
- **Momentum & Breadth**: Gainers/losers analysis
- **Top 10 Gainers/Losers**: With price and change %
- **Sector Rotation**: Top 10 crypto sectors
- **Trending Coins**: Real-time trending from CoinGecko

## ⏰ Update Schedule
- The static report is generated hourly, at minute zero UTC (GitHub scheduling may be delayed), on pushes to `master`, or by manual workflow dispatch.
- The checked-in live dashboard polls CoinGecko every 30 seconds, with exponential backoff after errors. It is separate from the deployed static report.

## 🚀 How It Works
1. GitHub Actions runs hourly, on pushes to `master`, or manually
2. Fetches data from CoinGecko API
3. Generates HTML report
4. Deploys to GitHub Pages

## 🛠️ Local Development
```bash
python3 -m pip install -r requirements.txt
python3 -m unittest -v
# Optional dashboard regression checks (requires Node.js):
node tests/dashboard_check.js
python3 generate_html_report.py --output _site/index.html
python3 -m http.server 8000 --directory _site
# Open http://localhost:8000 for the static report
```

Generation requires network access to the public CoinGecko API (no key). HTTP 429 and 5xx responses are retried with bounded exponential backoff; persistent API failures exit with a clear error. The tests mock requests and run offline once dependencies are installed.

`--output` defaults to `index.html` in the current directory, which would overwrite the checked-in live dashboard. Use `_site/index.html` as above to preserve it. The workflow uploads only `_site/`.

To view the separate live dashboard, run `python3 -m http.server 8000` from the repository root. Browser API requests require network access and are subject to CoinGecko rate limits. Failed refreshes retain the last good data and show an error banner.
